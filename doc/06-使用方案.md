# 使用方案

## 1. 平台使用角色

- 超级管理员：初始化系统、维护用户角色、配置系统参数。
- 运维管理员：维护产品仓库、部署方案、客户环境、生成部署包。
- 实施工程师：下载部署包、安装 Agent、执行现场部署、查看日志。
- 查看用户：查看授权范围内的客户、环境、部署包和日志。

## 2. 超级管理员使用流程

### 2.1 初始化组织和权限

1. 登录平台。
2. 创建公司、部门、岗位。
3. 创建角色，例如超级管理员、运维管理员、实施工程师、查看用户。
4. 为角色分配菜单、按钮和接口权限。
5. 创建用户并绑定角色。

### 2.2 权限维护

1. 进入角色管理。
2. 选择角色。
3. 调整菜单权限、按钮权限、数据权限。
4. 保存后用户重新登录生效。

## 3. 运维管理员使用流程

### 3.1 维护产品仓库

1. 进入产品仓库。
2. 新建资源，填写资源名称、类型、来源。
3. 上传 jar、脚本、配置模板等文件，或从 Harbor 同步镜像。
4. 录入版本号和版本说明。
5. 保存资源版本。

### 3.2 配置部署方案

1. 进入部署配置管理。
2. 新建部署方案。
3. 添加部署组件，如应用服务、MySQL、Redis、Nginx、初始化脚本。
4. 为每个组件选择产品资源版本。
5. 设置部署顺序、配置模板、环境变量和健康检查规则。
6. 发布部署方案版本。

### 3.3 维护客户和环境

1. 进入客户管理。
2. 新建客户并录入基础信息。
3. 在客户下创建环境，如测试环境、生产环境。
4. 录入服务器、数据库、中间件、网络和目录信息。
5. 绑定部署方案版本。
6. 保存环境配置。

### 3.4 生成部署包

1. 进入部署包管理。
2. 点击生成部署包。
3. 选择客户、客户环境、部署方案版本。
4. 填写部署包版本和说明。
5. 提交生成任务。
6. 等待生成完成后下载部署包。

## 4. 实施工程师使用流程

### 4.1 下载部署包

1. 登录平台。
2. 进入部署包管理。
3. 按客户、环境、版本筛选部署包。
4. 下载部署包。部署包生成后不可变，如果部署资源或配置有变化，需要重新生成新版本部署包。
5. 将部署包带到客户现场服务器。

### 4.2 客户现场离线部署

1. 在客户现场服务器安装 Agent。
2. 将部署包上传到服务器指定目录。
3. 执行 Agent 导入命令。
4. Agent 自动校验部署包完整性。
5. 执行环境检测。
6. 环境检测通过后执行部署。
7. 查看部署结果和健康检查报告。
8. 如果部署失败，先根据失败步骤修复现场问题，再使用续跑命令从失败步骤继续执行。

示例命令：

```bash
agent import --package delivery-package.zip
agent check --package delivery-package.zip
agent deploy --package delivery-package.zip
agent resume --task latest
agent report --task latest
```

### 4.3 客户现场在线部署

在线部署属于后续增强能力，MVP 阶段优先使用离线部署包模式。

1. 获取平台生成的 Agent 注册码。
2. 在客户现场服务器安装 Agent。
3. 使用注册码注册 Agent。
4. 在平台选择 Agent 并下发部署任务。
5. 在平台实时查看执行日志和状态。

示例命令：

```bash
agent register --server https://platform.example.com --token <register-token>
agent start
```

## 5. 日志查看

### 5.1 操作日志

用于查看用户在平台中的新增、修改、删除、生成部署包等行为。

### 5.2 下载日志

用于查看部署包或资源文件的下载记录，包括下载人、下载时间、IP、客户环境等。

### 5.3 Agent 执行日志

用于查看 Agent 每个执行步骤的日志、状态、耗时、错误信息和最终结果。

## 6. 常见异常处理

| 异常 | 处理方式 |
| --- | --- |
| 部署包校验失败 | 重新下载部署包，确认传输过程未损坏 |
| 环境检测失败 | 根据检测报告补齐依赖、开放端口或调整磁盘空间 |
| 镜像加载失败 | 检查 Docker 是否安装、镜像文件是否完整 |
| 数据库初始化失败 | 检查数据库连接、账号权限和 SQL 脚本 |
| 服务启动失败 | 查看 Agent 日志和应用日志，确认端口、配置和依赖 |
| Agent 无法注册 | 检查网络连通性、平台地址、注册码是否有效 |
