# 开发计划

## 1. 建设阶段划分

建议按“最小闭环优先、离线部署优先、在线管控后置”的方式分阶段建设。第一版聚焦企业私有化交付编排中心，不重复建设 Harbor、Nexus、CMDB、监控等系统能力。

## 2. 第一阶段：MVP 核心闭环

### 2.1 建设目标

完成从产品资源索引、部署方案版本化、客户环境配置、不可变部署包生成到 Agent 离线部署的最小业务闭环。

### 2.2 功能范围

- 用户登录、退出、个人信息；
- 基础角色权限，不做复杂组织和数据权限；
- 产品仓库资源元数据管理；
- 文件上传、下载、校验；
- Harbor 镜像信息引用或同步；
- 客户基础信息管理；
- 客户环境基础信息管理；
- 部署方案管理和版本发布；
- 部署组件、部署步骤、配置模板和环境变量；
- 部署包生成、manifest.json、checksum.sha256；
- 部署包不可变版本管理；
- Agent 离线导入部署包；
- Agent 环境检测、幂等执行、失败续跑、健康检查；
- 本地部署报告；
- 操作日志和下载日志。

### 2.3 交付物

- 后端基础工程；
- 前端管理端基础框架；
- 数据库初始化脚本；
- 基础用户权限模块；
- 产品资源索引模块；
- 客户和环境模块；
- 部署配置管理模块；
- 部署包生成服务；
- 部署包 manifest.json 规范；
- Agent 离线执行器；
- 执行日志和部署报告模板。

## 3. 第二阶段：在线 Agent 管理与日志增强

### 3.1 建设目标

在离线部署稳定后，增加 Agent 在线注册、心跳、任务下发和实时日志能力。

### 3.2 功能范围

- Agent 注册和认证；
- Agent 心跳；
- 平台下发任务；
- Agent 状态上报；
- 实时日志展示；
- 任务取消；
- 部署结果归档；
- 失败重试策略。

### 3.3 交付物

- Agent 管理模块；
- 在线任务接口；
- 实时日志能力；
- Agent 安全注册机制；
- 部署任务看板。

## 4. 第三阶段：安全、治理和运营能力

### 4.1 建设目标

在核心交付闭环和在线 Agent 能力稳定后，增强平台安全、治理、统计和运维能力。

### 4.2 功能范围

- 敏感配置加密和密钥轮换；
- 审计日志增强；
- 数据权限增强；
- 系统监控；
- 部署成功率统计；
- 常见失败原因分析；
- 部署包生命周期管理；
- 文件清理策略；
- 备份恢复策略；
- 自动回滚能力评估和试点。

### 4.3 交付物

- 安全配置管理；
- 审计和统计报表；
- 运维监控指标；
- 生命周期管理策略；
- 回滚方案设计。

## 5. 暂缓能力清单

以下能力不进入 MVP，避免第一版范围过大：

- 完整替代 Harbor、Nexus、Maven 仓库；
- 复杂公司、部门、岗位和数据权限；
- 在线 Agent 任务下发和实时日志；
- 自动回滚；
- Kubernetes 编排；
- 统计分析大屏；
- 远程运维平台能力。

## 6. 优先级建议

| 优先级 | 功能 | 原因 |
| --- | --- | --- |
| P0 | 产品资源索引、部署方案版本化、客户环境、部署包生成、Agent 离线部署 | 构成平台最小业务闭环 |
| P1 | 环境检测、幂等执行、失败续跑、部署报告、日志审计 | 直接提升现场交付稳定性 |
| P2 | Agent 在线管理、实时日志、任务下发 | 增强远程管控能力 |
| P3 | 复杂数据权限、统计分析、生命周期管理、自动回滚 | 优化治理和运营能力 |

## 7. 验收标准

- 能维护产品资源并上传 jar、脚本、配置模板等文件。
- 能引用或同步 Harbor 镜像信息。
- 能创建客户和多个独立客户环境。
- 能配置部署方案并绑定资源版本。
- 能按客户环境生成部署包。
- 能下载部署包并记录下载日志。
- 部署方案发布后不可直接修改，只能创建新版本。
- 客户环境绑定明确的部署方案版本。
- 部署包包含 manifest.json 和 checksum.sha256。
- 部署包生成成功后不可变，变更内容必须重新生成新包。
- Agent 能导入部署包并执行环境检测。
- Agent 能按部署清单执行部署步骤并生成日志。
- Agent 支持幂等执行和失败续跑。
- 敏感配置不明文出现在普通日志中。
- 不同角色登录后只能访问授权功能。
- 关键操作均可在审计日志中查询。
