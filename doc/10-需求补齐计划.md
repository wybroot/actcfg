# 需求补齐计划（Gap-Closing Plan）

> 基准：《需求描述.docx》8 大核心需求
> 现状：MVP 骨架阶段，数据模型领先于业务实现
> 日期：2026-07-20

## 关键决策（已确认）

1. **绑定策略**：保留部署方案的复用/克隆能力；客户绑定方案时生成**独立副本快照**（`customer_deploy_snapshot`），后续修改互不干扰。放弃"全局独占锁"方案。
2. **Agent 模式**：离线包模式与在线全自动 Agent **都纳入首版**，分阶段交付（离线先，在线紧随）。
3. 本文档为补齐路线图，供后续开发对照。

## 分阶段补齐计划

### 阶段一：打地基（安全 + 核心 CRUD 闭环）
优先级最高，其他功能都依赖它。

- **需求8 用户中心 RBAC**（最优先）
  - 引入 Spring Security + JWT，替换 `AuthController` 硬编码 `dev-token`。
  - 用户表加密码字段（BCrypt），实现登录密码校验、`/api/auth/profile` 真实读取当前用户。
  - 用户/角色 CRUD 接口 + 前端 `system/UserListView.vue` 落地。
  - 四角色权限：超级管理员（全权）、运维（需求1-6操作权）、实施工程师（查看+执行部署）、审计人员（仅查看）。新增独立"审计人员"角色。
  - 方法级权限：`@PreAuthorize` / 自定义权限注解 + `SecurityConfig`。
  - 个人信息维护接口（改昵称/密码）。
- **需求3 客户管理**
  - 补客户新增/修改/删除接口（`CustomerController` 现仅只读），软删除。
  - 客户联系人/运维信息维护。
  - 前端 `customer/CustomerListView.vue` 从占位升级为可操作页。

### 阶段二：制品与配置能力真实化
- **需求1 制品仓库**
  - 真实文件上传（`MultipartFile` + MinIO），支持 jar/镜像tar/SQL/脚本/配置多类型。
  - Harbor 同步：调用 Harbor API 拉取镜像元数据（并明确"同步元数据 vs 拉取镜像层"边界）。
  - 上传后计算 checksum、大小、类型识别。
- **需求2 环境变量配置**
  - 环境变量/配置/DB脚本的**写接口**（增删改），`CustomerService` 现仅 list。
  - **克隆/复制**功能：方案层配置模板克隆、客户环境变量整组复制。
  - DB 初始化脚本作为可管理的配置项挂到组件/方案上。

### 阶段三：客户配置中心 + 发布中心闭环
- **需求4 客户配置生成中心**（按决策1实现）
  - 新增 `customer_deploy_snapshot` 表：客户绑定方案版本时，深拷贝方案+组件+配置模板为独立副本。
  - 绑定后客户在快照上编辑环境变量，与源方案解耦。
  - 集中式"配置工作台"页面：选客户 → 关联组件 → 填环境变量 → 保存快照。
  - 保留方案复用/克隆能力（不加全局独占锁）。
- **需求5 发布中心**
  - 从 manifest 升级为**真实压缩部署包**（tar.gz/zip：含镜像、jar、SQL、渲染后配置、agent、manifest、校验和）。
  - 一键生成异步任务 + 进度反馈。
  - 下载路径串联 `audit_download_log` 落库（对接需求7）。

### 阶段四：Agent 双模式
- **需求6 离线 Agent**（先）
  - 打包可执行 agent（脚本/二进制）进部署包。
  - agent 端：环境检测（OS/CPU/磁盘/Docker/端口）、包与目标环境兼容性校验、镜像加载、配置渲染、DB初始化、健康检查、幂等、失败续跑。
  - 现有任务状态机/上报/续跑已具备，补齐真实执行器。
- **需求6 在线 Agent**（后，按决策2纳入首版）
  - agent 下载中心：现场联网时下载 agent。
  - agent 主动连平台拉取任务、实时回传状态、自动完成全流程"无脑部署"。
  - 平台侧任务下发 + 在线心跳/实例管理（`agent_instance`）。

### 阶段五：审计与可视化
- **需求7 日志记录**
  - `AuditService` 去掉硬编码假数据，`audit_operation_log` / `audit_download_log` 真实落库。
  - `@AuditLog` 注解 + AOP 拦截自动记录操作日志。
  - 补登录日志表 `sys_login_log`。
  - agent 部署记录已较完整，串联为统一审计视图。
  - 前端 `audit/AuditLogView.vue` 落地，支持按人/时间/客户溯源。
- **Dashboard 大屏**：交付概览、任务状态、部署统计。

## 里程碑建议顺序
阶段一 → 阶段二 → 阶段三 → 阶段四（离线）→ 阶段五 → 阶段四（在线）

安全（阶段一）必须最先，因为它是所有操作权限的前提；在线 Agent 放最后是因为它依赖离线执行器和发布中心的真实产物。

## P3 后置能力（五大阶段收官后补充，2026-07-21）

五大阶段 + 在线 Agent 全部完成后，继续实现原 doc/07 中列为 P3 的后置能力：

- **部署包生命周期管理**：状态机 `ACTIVE→ARCHIVED→DEPRECATED→PURGED` + 下载计数 + 保留期 + 超管清理（`V8`）。
- **统计分析（成功率 + 失败归因）**：`GET /api/stats/deploy` 基于已结束任务算成功率，失败步骤/原因 Top5 归因，Dashboard 展示。
- **敏感配置加密 + 密钥轮换**：AES-256-GCM，密文自带密钥版本支持轮换，敏感变量入库前加密、内部解密、对外脱敏；超管一键轮换接口。
- **实时日志（SSE）**：agent 上报状态时按任务广播到前端 EventSource，实时观看部署进度。
- **源仓库前端可管理**：源仓库（Harbor 类型）做成前端可增删改实体，密码加密存储、测试连接、同步时选择源仓库；镜像坐标接入离线部署脚本（有 tar 则 `docker load`，否则按坐标 `docker pull`）。**取向：平台只同步元数据，不搬运/替代 Harbor/Nexus。**

仍未做的 P3/增量：复杂数据权限、自动回滚、真实 agent 客户端二进制、审计查询筛选、registry 代理形态。
