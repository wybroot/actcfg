# 数据库设计方案

## 1. 设计原则

- 业务数据与大文件分离，数据库仅保存文件元数据、外部仓库引用地址和存储路径。
- 所有核心表保留创建人、创建时间、更新人、更新时间、删除标记。
- 部署方案和资源版本化；部署包一旦生成即不可变，只允许新增新版本部署包。
- 已发布部署方案版本只读，客户环境绑定明确的部署方案版本。
- 客户环境之间数据隔离，客户环境变量与部署方案模板分层管理。
- Agent 执行步骤需要记录状态，支持幂等执行和失败续跑。
- 敏感配置加密存储或仅保存占位符，日志和接口返回时必须脱敏。
- 关键操作通过日志表记录，满足审计要求。

## 4. 主要关系

- 一个客户可拥有多个客户环境。
- 一个客户环境绑定一个已发布的部署方案版本。
- 一个部署方案版本包含多个部署组件和部署步骤，发布后只读。
- 一个部署组件引用一个产品资源版本。
- 一个部署包对应一个客户环境和一个部署方案版本，生成成功后不可变。
- 一个部署包拥有一份 manifest 清单和 checksum 校验文件。
- 一个 Agent 实例绑定一个客户环境。
- 一个 Agent 任务引用一个部署包并由一个 Agent 执行。
- 一个 Agent 任务包含多条步骤执行日志，用于支持失败续跑和审计。

## 5. 索引建议

- repo_resource.resource_code 唯一索引。
- repo_resource_version(resource_id, version) 唯一索引。
- deploy_plan.plan_code 唯一索引。
- deploy_plan_version(plan_id, version) 唯一索引。
- customer.customer_code 唯一索引。
- customer_environment(customer_id, environment_type) 普通索引。
- package_build(customer_id, environment_id, created_at) 普通索引。
- agent_instance(agent_code) 唯一索引。
- agent_task(agent_id, task_status, created_at) 普通索引。
- audit_operation_log(operator_id, created_at) 普通索引。
