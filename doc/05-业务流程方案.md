# 业务流程方案

## 1. 产品资源入库流程

```text
运维管理员登录平台
  -> 新建产品资源
  -> 选择资源类型
  -> 上传文件或从 Harbor/内部仓库同步
  -> 系统计算文件校验和
  -> 生成资源版本
  -> 资源入库完成
```

关键控制点：

- 同一资源下版本号不可重复。
- 文件上传后必须计算 SHA256。
- 镜像类资源需要记录镜像仓库、镜像名称、标签。
- 删除资源前应检查是否被部署方案引用。

## 2. 部署方案配置流程

```text
运维管理员创建部署方案
  -> 添加组件
  -> 选择组件依赖的产品资源版本
  -> 配置部署顺序
  -> 维护配置模板和环境变量
  -> 设置健康检查规则
  -> 发布部署方案版本
```

关键控制点：

- 已发布版本不可直接修改，需要创建新版本。
- 客户环境只能绑定已发布的具体方案版本。
- 方案可复制或克隆，用于快速创建相似客户方案。
- 部署步骤要保持顺序明确，避免执行依赖混乱。

## 3. 客户和环境配置流程

```text
维护客户基础信息
  -> 创建客户环境
  -> 录入服务器、数据库、中间件、网络信息
  -> 维护环境变量
  -> 绑定部署方案版本
  -> 校验环境配置完整性
```

关键控制点：

- 每个客户可存在多个独立环境。
- 环境变量按环境隔离，避免不同客户共用配置导致混淆。
- 生产环境配置变更应记录操作日志。

## 4. 部署包生成流程

```text
选择客户
  -> 选择客户环境
  -> 选择部署方案版本
  -> 系统收集资源文件
  -> 渲染客户环境配置
  -> 生成 Agent 执行清单
  -> 打包压缩
  -> 生成校验文件
  -> 提供下载
```

部署包建议目录结构：

```text
delivery-package.zip
  |-- manifest.json
  |-- checksum.sha256
  |-- resources/
  |   |-- apps/
  |   |-- images/
  |   |-- sql/
  |   |-- scripts/
  |-- config/
  |-- agent/
  |-- docs/
```

- 部署包生成成功后不可变，任何资源、配置或脚本变化都需要生成新包。
- manifest.json 是 Agent 执行的唯一依据，Agent 不应依赖目录猜测部署步骤。
- checksum.sha256 用于校验部署包传输和拷贝后的完整性。
- 敏感配置应加密、占位或部署时输入，不能明文写入普通日志。

manifest.json 示例：

```json
{
  "packageCode": "PKG202607170001",
  "customerCode": "CUST001",
  "environment": "PROD",
  "deployPlanVersion": "v1.0.0",
  "steps": [
    {"order": 1, "type": "CHECK_ENV", "name": "环境检测"},
    {"order": 2, "type": "LOAD_IMAGE", "name": "加载镜像"},
    {"order": 3, "type": "RUN_SQL", "name": "初始化数据库"},
    {"order": 4, "type": "START_SERVICE", "name": "启动服务"},
    {"order": 5, "type": "HEALTH_CHECK", "name": "健康检查"}
  ]
}
```

## 5. 客户现场 Agent 部署流程

### 5.1 离线部署流程

```text
实施工程师下载部署包
  -> 拷贝到客户现场服务器
  -> 安装或启动 Agent
  -> 导入部署包
  -> Agent 校验部署包
  -> Agent 执行环境检测
  -> Agent 自动部署
  -> Agent 输出部署报告
  -> 实施工程师确认结果
```

### 5.2 Agent 幂等与失败续跑流程

```text
Agent 读取 manifest.json
  -> 查询本地步骤状态
  -> 已成功步骤执行状态校验
  -> 未执行或失败步骤继续执行
  -> 每个步骤完成后写入状态
  -> 失败时记录失败原因和可续跑位置
```

关键控制点：

- 目录、镜像、SQL、服务启动等步骤必须具备重复执行安全性。
- 失败后默认从失败步骤继续，不应从头破坏性重跑。
- 允许实施工程师手动选择重新执行、跳过或从指定步骤继续。
- 每次续跑都需要生成独立执行记录。

### 5.3 在线部署流程

```text
现场安装 Agent
  -> Agent 使用注册码注册到平台
  -> 平台下发部署任务
  -> Agent 拉取任务和资源
  -> Agent 执行部署
  -> Agent 实时上报日志和状态
  -> 平台展示部署结果
```

## 6. 日志审计流程

```text
用户执行操作
  -> 后端拦截器记录操作人、IP、接口、参数摘要
  -> 保存操作日志

用户下载部署包
  -> 校验权限
  -> 返回文件流
  -> 保存下载日志

Agent 执行任务
  -> 上报步骤日志
  -> 更新任务状态
  -> 任务完成后生成执行报告
```

## 7. 权限管理流程

```text
超级管理员创建角色
  -> 分配菜单权限和按钮权限
  -> 创建用户
  -> 绑定公司、部门、岗位
  -> 分配角色
  -> 用户登录后按权限访问功能
```

权限控制建议：

- 菜单级权限控制页面是否可见。
- 按钮级权限控制新增、修改、删除、下载、生成部署包等操作。
- 数据级权限控制用户可访问的客户、环境范围。
- 接口级权限作为最终安全边界。
