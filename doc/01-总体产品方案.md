# 企业私有化交付编排与自动部署平台总体产品方案

## 1. 建设背景

公司当前产品交付主要依赖实施工程师在客户现场手工准备部署介质、配置文件、初始化脚本和运行命令。随着客户数量增加、交付环境多样化，传统方式容易出现版本不一致、配置遗漏、现场操作不可追溯、重复劳动多等问题。

本平台面向“交付资源索引、部署方案编排、客户环境配置、离线部署包生成、Agent 自动化执行、日志审计”核心链路，建设企业私有化交付编排与自动部署平台。平台定位为交付编排中心：不重复建设 Harbor、Nexus、CMDB、监控平台等系统，而是复用既有制品仓库和基础设施，将交付资源组织成客户现场可执行、可追溯、可复用的标准化部署包。

## 2. 建设目标

- 建设企业私有化交付编排中心，统一组织产品资源、部署方案、客户环境和现场部署执行。
- 将产品仓库定位为交付资源索引和编排入口，避免重复建设 Harbor、Nexus 等制品仓库能力。
- 支持部署方案版本化，已发布版本不可直接修改，客户环境绑定明确的方案版本。
- 支持按客户环境生成不可变部署包，部署包包含 manifest 清单、校验文件、资源文件、配置文件和执行说明。
- 优先支持 Agent 离线部署模式，满足客户现场内网、弱网、不可联网等交付场景。
- 提供 Agent 环境检测、幂等执行、失败续跑、健康检查和部署报告能力。
- 完整记录资源上传、部署包生成、下载、Agent 执行、权限变更等关键日志，满足审计和问题追踪。
- 建立基础 RBAC 权限体系，先满足角色级功能权限，复杂组织和数据权限作为后续增强。

## 3. 目标用户

| 用户角色 | 主要职责 |
| --- | --- |
| 超级管理员 | 维护系统基础配置、用户权限、全局资源与审计数据 |
| 运维管理员 | 维护产品仓库、部署方案、客户环境、部署包、Agent 任务 |
| 实施工程师 | 查看交付方案、下载部署包、现场执行 Agent 部署、查看执行日志 |
| 普通查看用户 | 查看被授权的客户、环境、方案和日志信息 |

## 4. 核心业务模块

### 4.1 产品仓库

产品仓库不定位为完整制品仓库，而是作为交付资源的索引、引用和编排入口。镜像仍由 Harbor 管理，jar 包可继续来自 Nexus、Maven 仓库或内部文件库，平台重点保存资源元数据、版本、来源、校验值和引用关系。

用于维护交付所需的各类资源，包括：

- jar 包、war 包等应用制品；
- Docker 镜像、镜像元数据和 Harbor 导入记录；
- 数据库初始化 SQL、升级脚本、回滚脚本；
- 配置模板、启动脚本、安装脚本；
- 离线依赖包、组件安装包等。

资源支持以下来源：

- 手工上传；
- 从公司内部仓库同步；
- 从 Harbor 导入镜像信息或镜像包；
- 后续可扩展 Maven、Nexus、制品库等来源。

### 4.2 部署配置管理

根据产品仓库中的资源，编排具体部署方案。典型配置包括：

- 应用服务包及启动参数；
- MySQL、Redis、Nginx 等中间件镜像或安装包；
- 数据库初始化脚本、升级脚本；
- 配置文件模板与变量；
- 服务依赖关系和部署顺序；
- 环境变量、端口、挂载路径、健康检查规则。

部署配置支持克隆、复制和版本化，便于不同客户或不同环境复用已有配置。部署方案一旦发布即不可直接修改，后续调整必须创建新版本；客户环境绑定具体方案版本，保证历史部署可追溯。

### 4.3 客户管理

维护客户基础信息和运维信息，包括：

- 客户名称、简称、行业、联系人；
- 项目编号、合同编号、服务周期；
- 客户现场网络、服务器、数据库、中间件等运维信息；
- 客户对应的交付环境和历史部署记录。

### 4.4 客户环境配置

客户环境描述“部署到哪里”，部署方案描述“产品怎么部署”，二者必须分层管理。平台通过“部署方案模板 + 客户环境变量”生成客户专属部署包。

在客户下创建一个或多个部署环境，例如开发、测试、生产、灾备等。每个环境维护独立配置，避免不同客户或不同环境之间互相影响。

环境配置包括：

- 环境名称、环境类型、归属客户；
- 服务器清单、IP、操作系统、CPU、内存、磁盘；
- 部署目录、数据目录、日志目录；
- 数据库连接、中间件地址；
- 域名、端口、证书、网络策略；
- 与部署配置的绑定关系。

### 4.5 部署包生成

选择已经配置好的客户环境和部署方案，生成可下载的部署包。部署包主要用于客户现场离线或半离线交付。

部署包内容包括：

- manifest.json 机器可读清单，描述客户、环境、方案版本、资源、步骤和校验信息；
- 产品制品、镜像或镜像清单；
- 初始化脚本、升级脚本；
- 客户环境专属配置文件；
- Agent 执行清单；
- checksum.sha256 校验文件；
- 部署说明、版本信息和离线执行命令。

部署包一旦生成即不可变。任何资源、配置或脚本变更都需要重新生成新版本部署包。

### 4.6 Agent 自动化部署

Agent 面向客户现场执行自动化部署。第一版优先支持离线模式：实施工程师下载部署包并拷贝到客户现场，Agent 导入部署包后本地执行环境检测、部署和报告生成。在线注册、任务下发和实时日志作为后续增强能力。

Agent 能力包括：

- 环境检测：系统版本、磁盘、端口、Docker、网络连通性等；
- 资源准备：解压部署包、加载镜像、初始化目录；
- 配置渲染：根据客户环境变量生成最终配置；
- 自动部署：按部署清单执行安装、启动、初始化；
- 幂等执行：已成功步骤重复执行时应检查状态并跳过或安全更新；
- 失败续跑：部署失败后支持从失败步骤继续执行；
- 健康检查：检测服务端口、进程、接口、容器状态；
- 本地报告：在客户现场生成可导出的部署报告；
- 日志记录：记录执行步骤、输出、错误信息和结果，在线模式下可回传平台。

### 4.7 日志记录与审计

记录平台和 Agent 相关行为，包括：

- 人工操作日志；
- 文件上传、下载、删除记录；
- 部署包生成记录；
- Agent 任务执行日志；
- 用户登录、权限变更、角色调整记录。

### 4.8 用户权限管理

支持用户、角色、公司、岗位等组织权限模型。示例权限：

- 超级管理员：拥有全部操作权限；
- 运维管理员：拥有产品仓库、部署配置、客户管理、环境配置、部署包、Agent 管理等权限；
- 实施工程师：拥有客户环境、部署包、Agent 任务、日志查看等权限；
- 普通用户：仅拥有查看授权范围内数据的权限。

## 5. MVP 功能边界

第一版优先完成最小可用闭环：

```text
产品资源索引
  -> 部署方案版本化编排
  -> 客户环境变量配置
  -> 不可变部署包生成
  -> Agent 离线环境检测与自动部署
  -> 执行日志和部署报告
```

### 5.1 MVP 必做能力

- 用户登录和基础角色权限；
- 产品资源管理，包括 jar、镜像信息、SQL、脚本、配置模板；
- 部署方案管理，包括组件、步骤、资源版本引用、配置模板；
- 客户和客户环境管理；
- 部署包生成、校验、下载和审计；
- Agent 离线导入部署包、环境检测、幂等执行、失败续跑、健康检查；
- Agent 本地日志和部署报告。

### 5.2 MVP 暂缓能力

- 在线 Agent 注册、心跳、任务下发；
- WebSocket 实时日志；
- 自动回滚；
- 复杂组织架构和复杂数据权限；
- 多制品仓库深度集成；
- 统计分析大屏；
- Kubernetes 编排和高级运维能力。

## 6. 产品价值

- 降低现场交付门槛，减少人为操作错误。
- 提升不同客户环境配置的一致性和可追溯性。
- 缩短部署准备和交付周期。
- 支持产品包、部署方案、客户环境的统一沉淀和复用。
- 为后续自动化运维、远程升级、交付质量分析提供基础能力。
