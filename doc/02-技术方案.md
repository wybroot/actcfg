# 企业私有化交付编排与自动部署平台技术方案

## 1. 总体架构

平台采用前后端分离架构，由管理端 Web、后端服务、对象存储、关系型数据库、制品仓库对接模块、Agent 客户端组成。平台不替代 Harbor、Nexus、Maven 仓库、CMDB、监控平台等已有系统，而是作为交付编排中心，负责资源引用、方案编排、客户环境渲染、部署包生成和 Agent 执行协同。

```text
用户浏览器
   |
   | HTTPS
   v
管理端 Web
   |
   | REST API
   v
后端服务
   |-------------- MySQL：业务数据、权限、日志索引
   |-------------- 对象存储/文件存储：jar、脚本、部署包、配置模板
   |-------------- Harbor/Nexus/内部仓库：资源元数据同步和引用，不重复建设完整制品仓库
   |-------------- Agent 通信接口：在线模式下任务下发、日志回传、状态上报

客户现场
   |
   v
Agent：环境检测、部署执行、健康检查、日志采集
```

## 2. 技术选型建议

| 层级 | 推荐技术 | 说明 |
| --- | --- | --- |
| 前端 | Vue 3 / React + TypeScript | 构建后台管理系统 |
| 后端 | Java Spring Boot / Spring Cloud | 适合企业级管理平台和权限体系 |
| 数据库 | MySQL 8.x | 存储业务数据、权限、日志索引 |
| 文件存储 | MinIO / 本地 NAS / 对象存储 | 存储大文件和部署包 |
| 缓存 | Redis | 会话、任务状态、短期缓存 |
| 镜像仓库 | Harbor | 对接公司内部镜像资源 |
| Agent | Go / Java | Go 更适合单文件分发，Java 便于复用企业技术栈 |
| 通信协议 | HTTPS REST，后续可扩展 WebSocket | MVP 优先 REST；WebSocket 用于后续实时日志 |
| 认证授权 | JWT + RBAC | 支持接口鉴权和角色权限控制 |

## 3. 后端服务划分

### 3.1 用户权限服务

- 用户管理；
- 角色管理；
- 菜单权限；
- 接口权限；
- 公司、部门、岗位维护；
- 登录认证、Token 签发、密码策略。

### 3.2 产品仓库服务

- 维护资源元数据、版本、来源地址和校验值；
- 手工上传交付资源文件；
- 引用 Harbor 镜像、Nexus/Maven 制品、内部仓库文件；
- 资源版本管理；
- 资源类型管理；
- 文件校验和计算；
- 记录资源被部署方案引用的关系；
- 删除前检查引用，避免破坏历史方案和部署包。

产品仓库服务不负责替代 Harbor/Nexus 的制品存储、镜像扫描、制品发布等能力。

### 3.3 部署配置服务

- 部署方案创建、编辑、复制、克隆；
- 服务组件编排；
- 配置模板变量维护；
- 部署步骤编排；
- 方案版本管理；
- 发布版本只读控制；
- 客户环境与具体方案版本绑定。

### 3.4 客户环境服务

- 客户基础信息维护；
- 客户环境维护；
- 服务器、中间件、数据库、网络信息维护；
- 客户环境与部署方案绑定。

### 3.5 部署包服务

- 部署包生成任务；
- 资源收集与打包；
- 客户环境变量渲染；
- manifest.json 清单生成；
- checksum.sha256 校验文件生成；
- 敏感配置加密或占位处理；
- 部署包不可变版本管理；
- 部署包下载和历史版本管理。

### 3.6 Agent 管理服务

MVP 阶段以离线 Agent 为主，平台侧重点是生成部署包和记录部署结果。在线 Agent 能力作为后续增强。

MVP：

- Agent 安装包管理；
- 离线部署包执行规范；
- 本地日志和部署报告格式；
- 部署报告导入或归档。

后续增强：

- Agent 注册；
- Agent 心跳；
- 任务下发；
- 执行状态上报；
- 实时日志接收；
- 执行结果归档。

### 3.7 日志审计服务

- 操作日志；
- 登录日志；
- 下载日志；
- 部署执行日志；
- 权限变更日志。

## 4. Agent 技术设计

### 4.1 Agent 部署模式

MVP 优先支持离线模式：实施工程师下载部署包，在客户现场安装 Agent 后导入部署包执行。该模式适合客户现场内网、弱网、不可联网环境。

后续可扩展在线模式：Agent 注册到平台，由平台下发任务并接收执行日志。

### 4.2 Agent 执行流程

```text
安装 Agent
  -> 导入离线部署包
  -> 读取 manifest.json
  -> 校验 checksum.sha256
  -> 执行环境检测
  -> 准备目录和运行依赖
  -> 加载镜像或安装组件
  -> 渲染配置文件
  -> 执行数据库初始化脚本
  -> 启动应用服务
  -> 执行健康检查
  -> 记录步骤状态
  -> 输出部署报告
```

### 4.3 Agent 关键执行原则

#### 4.3.1 环境检测前置

部署前必须检测操作系统、CPU、内存、磁盘、Docker、端口占用、目录权限、数据库连通性、必要命令和网络策略。检测失败时默认中止部署，允许实施工程师在明确风险后人工确认继续。

#### 4.3.2 幂等执行

每个步骤需要具备可重复执行能力：

- 目录已存在时不重复创建或破坏原内容；
- 镜像已加载时校验镜像 ID 后跳过；
- SQL 已执行时通过版本表或执行记录判断是否跳过；
- 服务已启动时执行状态检查而不是重复启动；
- 配置文件已存在时按策略备份后覆盖。

#### 4.3.3 失败续跑

Agent 本地记录每个步骤的执行状态，支持失败后从失败步骤继续执行，避免从头重复执行所有步骤。步骤状态建议包括：PENDING、RUNNING、SUCCESS、FAILED、SKIPPED、RETRYING。

#### 4.3.4 部署报告

部署结束后生成本地报告，至少包含部署包编号、客户环境、执行时间、步骤结果、失败原因、日志路径和健康检查结果。

### 4.4 Agent 安全要求

- Agent 与平台通信必须使用 HTTPS。
- Agent 注册使用一次性注册码或客户环境 Token。
- Agent 上报日志时需要绑定任务 ID、环境 ID 和签名信息。
- 部署包需要包含 manifest.json 和 checksum.sha256，防止传输或拷贝过程中损坏。
- 敏感配置如数据库密码应加密存储、部署时输入或使用占位符替换；日志输出必须脱敏。

## 5. 文件存储设计

推荐将大文件从业务数据库中剥离，统一存储在对象存储或文件存储中。数据库仅保存文件元数据。

文件类型包括：

- 上传的产品制品；
- 镜像导出包；
- 配置模板；
- 数据库脚本；
- 生成的部署包；
- Agent 日志附件。

文件应保存以下元数据：

- 文件名；
- 文件类型；
- 文件大小；
- SHA256 校验和；
- 存储路径；
- 上传人；
- 上传时间；
- 所属资源版本。

## 6. 安全设计

- 所有接口统一鉴权。
- 使用 RBAC 控制菜单和按钮权限。
- 上传文件限制类型、大小，并进行校验。
- 下载部署包需要记录下载人、下载时间、IP、客户环境。
- 敏感信息加密存储，接口返回时脱敏。
- 关键操作需要审计，包括删除资源、生成部署包、权限变更。

## 7. 可扩展设计

- 产品资源来源可扩展为 Maven、Nexus、GitLab Package Registry 等，但平台只做引用和编排，不重复建设完整制品仓库。
- Agent 执行器采用插件化步骤，后续可扩展 Kubernetes、Docker Compose、裸机安装等模式。
- 部署包格式保持清单化，便于不同版本 Agent 兼容解析。
- 日志服务后续可对接 Elasticsearch 或 OpenSearch 进行检索分析。

## 8. MVP 范围控制

MVP 优先实现最小业务闭环：产品资源索引、部署方案版本、客户环境变量、部署包生成、Agent 离线部署、日志报告。以下能力暂缓到后续版本：

- 在线 Agent 注册、心跳和任务下发；
- WebSocket 实时日志；
- 自动回滚；
- 复杂组织架构、岗位体系和数据权限；
- 多制品仓库深度集成；
- 统计分析大屏；
- Kubernetes 编排和远程运维能力。
