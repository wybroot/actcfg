# 接口方案

## 1. 接口设计原则

- 接口统一使用 REST 风格。
- 请求和响应统一使用 JSON。
- 文件上传使用 multipart/form-data。
- 文件下载使用二进制流并记录审计日志。
- 所有业务接口都需要携带认证 Token。
- 列表接口统一支持分页、排序和条件查询。
- 部署方案发布后只读，修改必须创建新版本。
- 部署包生成成功后不可变，变更资源或配置需要重新生成新部署包。
- Agent 在线接口属于后续增强，MVP 优先支持离线部署包和本地执行报告。

## 2. 通用响应格式

```json
{
  "code": 0,
  "message": "success",
  "data": {},
  "traceId": "20260717120000123"
}
```

分页响应：

```json
{
  "code": 0,
  "message": "success",
  "data": {
    "total": 100,
    "pageNo": 1,
    "pageSize": 20,
    "records": []
  }
}
```

```http
Authorization: Bearer <token>
```

```json
{

  "message": "success",
  "data": {
    "fileId": 10001,
    "originalName": "app.jar",
    "sha256": "...",
    "fileSize": 204800

```

## 10. 接口错误码建议

| 错误码 | 说明 |
| --- | --- |
| 0 | 成功 |
| 400001 | 请求参数错误 |
| 401001 | 未登录或 Token 失效 |
| 403001 | 无操作权限 |
| 404001 | 数据不存在 |
| 409001 | 数据状态冲突 |
| 500001 | 系统内部错误 |
| 600001 | 文件上传失败 |
| 600002 | 部署包生成失败 |
| 700001 | Agent 未注册 |
| 700002 | Agent 任务执行失败 |
