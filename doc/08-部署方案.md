# 部署方案

## 1. 概述

企业私有化交付编排与自动部署平台，定位为交付编排中心。不替代 Harbor、Nexus、CMDB、监控平台等已有系统，而是负责统一组织产品资源、部署方案、客户环境、不可变部署包与 Agent 执行。

**运行时依赖**

| 组件 | 版本要求 | 用途 |
| --- | --- | --- |
| JDK | **21**（最低 17） | 运行后端 jar |
| MySQL | 8.0+ | 业务数据、RBAC、审计日志 |
| Redis | 6.x / 7.x | 会话缓存、任务状态 |
| MinIO | 最新 RELEASE | 部署包、制品文件存储 |
| Nginx | 1.22+ | 前端静态资源 + 反向代理 |

> **dev profile 无需任何外部依赖。** 使用 `--spring.profiles.active=dev` 启动时后端全部内存运行，适合本地开发和功能验证。

## 2. 快速启动（dev 模式，本地开发验证）

无需 MySQL / Redis / MinIO，5 分钟跑起来。

```bash
# 1. 构建后端
cd backend
mvn package -DskipTests

# 2. 启动后端（dev profile，全内存）
java -jar target/delivery-platform-0.1.0-SNAPSHOT.jar \
     --spring.profiles.active=dev

# 3. 启动前端
cd ../frontend
npm install
npm run dev
```

浏览器访问 `http://localhost:5173`，默认账号见第 7 节。

## 5. MySQL 初始化

```bash
# 创建数据库和账号
mysql -u root -p <<'SQL'
CREATE DATABASE IF NOT EXISTS delivery_platform
  CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;

CREATE USER IF NOT EXISTS 'delivery'@'%' IDENTIFIED BY 'your_strong_password';
GRANT ALL PRIVILEGES ON delivery_platform.* TO 'delivery'@'%';
FLUSH PRIVILEGES;
SQL
```

> 表结构和种子数据由 **Flyway** 在后端首次启动时自动执行（V1–V9 共 9 个迁移脚本），无需手动导入。

## 6. MinIO 初始化

```bash
# 启动 MinIO（单机模式）
mkdir -p /data/minio
docker run -d \
  --name minio \
  -p 9000:9000 \
  -p 9001:9001 \
  -v /data/minio:/data \
  -e "MINIO_ROOT_USER=admin" \
  -e "MINIO_ROOT_PASSWORD=your_strong_password" \
  quay.io/minio/minio server /data --console-address ":9001"
```

浏览器访问 `http://<IP>:9001` 创建以下 **4 个 Bucket**（或使用 mc 命令行）：

| Bucket 名称 | 用途 |
| --- | --- |
| `delivery-resources` | 制品文件（jar、脚本、配置等） |
| `delivery-packages` | 部署包 ZIP |
| `delivery-agent` | Agent 安装包 |
| `delivery-reports` | 执行报告 |

```bash
# mc 命令行方式建 bucket
mc alias set myminio http://localhost:9000 admin your_strong_password
mc mb myminio/delivery-resources
mc mb myminio/delivery-packages
mc mb myminio/delivery-agent
mc mb myminio/delivery-reports
```

## 7. 后端配置

### 7.1 配置文件位置

```
backend/src/main/resources/
├── application.yml          # 通用配置（profile 无关）
├── application-dev.yml      # dev profile：纯内存，无需外部依赖
└── application-local.yml    # local profile：连接真实 MySQL/Redis/MinIO
                             # ！gitignore，含真实密码，不入代码库
```

### 7.2 application-local.yml 参考模板

以下为 local（生产/测试）profile 的完整配置，按实际环境填写：

```yaml
spring:
  datasource:
    url: jdbc:mysql://127.0.0.1:3306/delivery_platform?useUnicode=true&characterEncoding=utf8&serverTimezone=Asia/Shanghai&allowPublicKeyRetrieval=true&useSSL=false
    username: delivery
    password: your_strong_password
    driver-class-name: com.mysql.cj.jdbc.Driver
  data:
    redis:
      host: 127.0.0.1
      port: 6379
      password: your_redis_password    # 无密码时删除此行
      database: 0
  flyway:
    enabled: true
    locations: classpath:db/migration
    baseline-on-migrate: true

app:
  jwt:
    secret: ${APP_JWT_SECRET:请替换为至少32字符的强随机字符串}
    expiration-hours: 8

  storage:
    type: minio
    package-retention-days: 90          # 部署包保留天数，超期废弃后可清理
    minio:
      endpoint: http://127.0.0.1:9000
      access-key: admin
      secret-key: your_minio_password
      buckets:
        resources: delivery-resources
        packages:  delivery-packages
        agents:    delivery-agent
        reports:   delivery-reports

  # 敏感配置加密密钥（AES-256，base64 编码 32 字节）
  # 生成方式：head -c 32 /dev/urandom | base64
  # 未配置时退化为进程内临时密钥（重启失效，仅测试用）
  encryption:
    active-key-id: v1
    keys:
      v1: ${APP_ENCRYPTION_KEY_V1:请替换为base64编码的32字节密钥}

  # Harbor 镜像同步（可选）
  # 不配置时同步接口退化为按坐标直接登记
  harbor:
    # base-url: https://harbor.example.com
    # username: admin
    # password: your_harbor_password
```

### 7.3 关键配置项说明

| 配置项 | 必填 | 说明 |
| --- | --- | --- |
| `spring.datasource.*` | 是 | MySQL 连接信息 |
| `spring.data.redis.*` | 是 | Redis 连接信息 |
| `app.jwt.secret` | 是 | JWT 签名密钥，**生产必须改，最少 32 字符** |
| `app.storage.minio.*` | 是（MinIO 存储时）| MinIO 连接与 bucket 配置 |
| `app.encryption.keys.*` | 推荐 | 敏感变量加密密钥；不配置则每次重启密钥不同（历史数据无法解密） |
| `app.harbor.*` | 否 | Harbor 同步；不配置则直接按坐标登记（离线场景适用） |

## 8. 启动后端

```bash
# 构建
cd backend
mvn package -DskipTests

# 启动（local profile）
java -jar target/delivery-platform-0.1.0-SNAPSHOT.jar \
     --spring.profiles.active=local

     -jar target/delivery-platform-0.1.0-SNAPSHOT.jar \
     --spring.profiles.active=local \
```

**验证后端正常**

```bash
curl http://localhost:8080/api/auth/login \
  -H "Content-Type: application/json" \
  -d '{"username":"admin","password":"Admin@123"}'
# 返回 "code":0 且含 token 字段则正常
```

## 10. Nginx 配置

```nginx
server {
    listen 80;
    server_name your-domain.com;

    # 前端静态资源
    root /opt/delivery/frontend/dist;
    index index.html;

    # 前端路由（Vue history 模式）
    location / {
        try_files $uri $uri/ /index.html;
    }

    # 后端 API 反向代理
    location /api/ {
        proxy_pass http://127.0.0.1:8080;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_read_timeout 300s;    # 建包等耗时操作需要较长超时
    }

    # 可选：HTTPS 配置
    # listen 443 ssl;
    # ssl_certificate     /etc/nginx/ssl/cert.pem;
    # ssl_certificate_key /etc/nginx/ssl/key.pem;
}
```

```bash
# 检查配置并重载
nginx -t && nginx -s reload
```

## 12. Docker Compose 一键部署（可选）

以下 compose 文件可快速拉起全部依赖服务，**不含后端 jar，需单独启动**。

```yaml
# docker-compose.yml
version: "3.8"
services:
  mysql:
    image: mysql:8.0
    environment:
      MYSQL_ROOT_PASSWORD: root_password
      MYSQL_DATABASE: delivery_platform
      MYSQL_USER: delivery
      MYSQL_PASSWORD: your_strong_password
    ports:
      - "3306:3306"
    volumes:
      - mysql_data:/var/lib/mysql

  redis:
    image: redis:7
    command: redis-server --requirepass your_redis_password
    ports:
      - "6379:6379"

  minio:
    image: quay.io/minio/minio
    command: server /data --console-address ":9001"
    environment:
      MINIO_ROOT_USER: admin
      MINIO_ROOT_PASSWORD: your_minio_password
    ports:
      - "9000:9000"
      - "9001:9001"
    volumes:
      - minio_data:/data

volumes:
  mysql_data:
  minio_data:
```

```bash
docker compose up -d
# 等待 30 秒后创建 MinIO bucket（见第 6 节），再启动后端
```

## 13. Agent 离线部署（客户现场）

### 13.1 准备部署包

在平台上：

1. **产品仓库** 注册资源并上传制品文件（jar / SQL / 配置）或同步 Harbor 镜像坐标
2. **部署配置** 创建部署方案 → 添加组件 → 发布版本
3. **客户环境** 创建客户 → 创建环境 → 绑定部署方案版本 → 填写环境变量
4. **部署包** 点击「生成部署包」→ 状态变为 SUCCESS 后下载

### 13.2 现场执行

```bash
# 1. 将部署包上传到客户服务器
scp PKG-xxxxxxxx.zip user@customer-server:/opt/deploy/

# 2. 解压
cd /opt/deploy
unzip PKG-xxxxxxxx.zip -d PKG-xxxxxxxx

# 3. 检查包内容
ls PKG-xxxxxxxx/
#  manifest.json          部署清单（组件、资源版本、环境信息）
#  agent/
#    deploy-agent.sh      可执行 bash 部署脚本
#    execution-plan.json  执行步骤 JSON
#  components/            各组件渲染后的配置文件
#  artifacts/             内嵌的制品二进制（如有）

# 4. 赋权并执行
cd PKG-xxxxxxxx
chmod +x agent/deploy-agent.sh
./agent/deploy-agent.sh
```

### 13.3 脚本特性

- **幂等**：每个步骤执行结果记录在 `.agent-state` 文件，重跑自动跳过已完成步骤
- **失败续跑**：修复问题后重新执行脚本，从失败步骤继续
- **执行报告**：部署结束后生成 `execution-report.json`，可导入平台归档

```bash
# 查看执行报告
cat execution-report.json

# 将报告导入平台（需能连接平台）
curl -X POST http://platform:8080/api/agents/offline/reports/import \
  -H "Authorization: Bearer <token>" \
  -H "Content-Type: application/json" \
  -d @execution-report.json
```

### 13.4 镜像类组件

脚本的镜像加载逻辑：

1. 若 `artifacts/` 目录下有 `.tar` 文件 → 执行 `docker load -i xxx.tar`（完全离线）
2. 无 tar 文件 → 使用 manifest 中记录的镜像坐标执行 `docker pull <repo>:<tag>`（需现场能访问 Harbor 或代理）

## 14. Agent 在线模式（可选）

在线模式下 Agent 主动连平台拉取任务，适合现场能访问平台的场景。

```bash
# 1. 在平台注册 Agent（或通过 API）
curl -X POST http://platform:8080/api/agents/offline/instances/register \
  -H "Authorization: Bearer <token>" \
  -H "Content-Type: application/json" \
  -d '{
    "agentCode": "AGENT-PROD-01",
    "hostname":  "customer-server-01",
    "customerId": 1,
    "environmentId": 1
  }'

# 2. 心跳保活（建议每 60 秒一次，超 90 秒无心跳自动标记 OFFLINE）
curl -X POST http://platform:8080/api/agents/offline/instances/AGENT-PROD-01/heartbeat \
  -H "Authorization: Bearer <token>"

# 3. 拉取并认领 PENDING 任务
curl -X POST http://platform:8080/api/agents/offline/instances/AGENT-PROD-01/claim \
  -H "Authorization: Bearer <token>"
# 返回待执行任务信息，再按任务 taskId 上报执行状态
```

## 15. 备份与恢复

### 15.1 备份清单

| 对象 | 备份方式 | 建议频率 |
| --- | --- | --- |
| MySQL 数据库 | `mysqldump` 全量 + binlog 增量 | 每日全量 + 实时 binlog |
| MinIO 对象存储 | `mc mirror` 或 MinIO 副本 | 每日同步到备份存储 |
| 后端配置文件 | `application-local.yml`（含密钥）| 安全存放，版本变更时更新 |
| 加密密钥 | `app.encryption.keys.*` | **务必单独保管**，密钥丢失则历史敏感数据不可解密 |

### 15.2 MySQL 备份示例

```bash
# 全量备份
mysqldump -u delivery -p delivery_platform \
  --single-transaction --routines --triggers \
  > /backup/delivery_$(date +%Y%m%d).sql

# 恢复
mysql -u delivery -p delivery_platform \
  < /backup/delivery_20260722.sql
```

### 15.3 部署包清理

部署包有生命周期保护：`ACTIVE → ARCHIVED → DEPRECATED → PURGED`。

- 超管调用 `POST /api/packages/cleanup` 触发清理（删除物理文件，保留元数据）
- 默认保留期 90 天，可通过 `app.storage.package-retention-days` 调整

## 17. 常见问题

**Q：启动时报 `Migration checksum mismatch for migration version N`**

```bash
# 修改了迁移文件后需要 repair
mvn flyway:repair \
  -Dflyway.url="jdbc:mysql://127.0.0.1:3306/delivery_platform?useSSL=false" \
  -Dflyway.user=delivery \
  -Dflyway.password=your_password
```

**Q：登录报"用户名或密码错误"但账号存在**

种子账号密码为 `Admin@123`，注意大小写和特殊字符。若仍失败，直接更新数据库：

```bash
# 使用平台生成的 BCrypt hash 更新（hash 对应 Admin@123）
mysql -u delivery -p delivery_platform -e "
UPDATE sys_user
SET password_hash = '\$2a\$10\$vVdNjsbkolsexq8EtXBG2enGD4lq5uuoZ8OTANc/OotENeta/UBZK'
WHERE username IN ('admin','ops','impl','auditor');"
```

**Q：建包成功但文件路径是 `packages/PKGxxx.zip`（相对路径）**

未配置 MinIO，正在使用本地存储模式（`app.storage.type` 未设为 `minio`）。本地存储下文件位于 `data/storage/packages/` 目录，属正常行为。配置 MinIO 后返回完整 HTTP URL。

**Q：敏感变量重启后无法解密**

使用了进程内临时密钥（未配置 `app.encryption.keys`）。临时密钥在每次重启后重新生成，历史密文无法解密。**生产环境必须配置持久密钥。**

## 18. Docker 部署（推荐用于快速调试与复杂环境）

项目根目录下 `docker/` 提供完整的 Docker 部署文件，支持两种模式：

| 文件 | 用途 |
| --- | --- |
| `docker-compose.deps.yml` | 仅启动依赖（MySQL + Redis + MinIO），后端在本地 IDE / 命令行运行 |
| `docker-compose.yml` | 全栈部署，后端和前端均构建为镜像 |
| `.env.example` | 环境变量模板，复制为 `.env` 后填入真实值 |
| `Dockerfile.backend` | 后端多阶段构建（Maven 编译 → JRE 精简镜像） |
| `Dockerfile.frontend` | 前端多阶段构建（Node 编译 → Nginx 静态服务） |
| `nginx/default.conf` | Nginx 配置（Vue history 路由 + `/api` 反代 + SSE 支持） |

### 18.1 模式一：仅启动依赖（适合本地调试）

后端在 IDE 或命令行以 `local` profile 运行，只用 Docker 管理 MySQL / Redis / MinIO。

```bash
cd docker/
cp .env.example .env
# 编辑 .env，至少填写各服务密码

docker compose -f docker-compose.deps.yml up -d
# 等待约 20 秒，MinIO bucket 自动创建完毕

# 更新 backend/src/main/resources/application-local.yml
# 将连接信息指向 127.0.0.1:3306 / 6379 / 9000

# 启动后端
cd ..
java -jar backend/target/delivery-platform-0.1.0-SNAPSHOT.jar \
     --spring.profiles.active=local
```

### 18.2 模式二：全栈 Docker 部署（一键拉起）

```bash
cd docker/
cp .env.example .env
# 编辑 .env，填写密码和密钥（重要！）
vim .env
```

**.env 必填项**：

```env
MYSQL_ROOT_PASSWORD=强密码
MYSQL_PASSWORD=强密码
REDIS_PASSWORD=强密码
MINIO_ROOT_PASSWORD=强密码
APP_JWT_SECRET=至少32字符的随机字符串
APP_ENCRYPTION_KEY_V1=head -c 32 /dev/urandom | base64 生成
```

```bash
# 构建镜像并启动（首次约 3–5 分钟，含 Maven/npm 下载）
docker compose up -d --build

# 查看启动日志
docker compose logs -f backend
```

| 服务 | 地址 |

| 平台 Web | http://localhost |

### 18.3 常用运维命令

```bash
# 查看所有服务状态
docker compose ps

# 查看后端日志（实时）
docker compose logs -f backend

# 重启后端（配置变更后）
docker compose restart backend

# 停止全部服务（保留数据卷）
docker compose down

# 停止并删除全部数据（慎用！）
docker compose down -v

# 单独重建后端镜像（代码更新后）
docker compose up -d --build backend

# 进入 MySQL
docker compose exec mysql mysql -u delivery -p delivery_platform
```

### 18.4 注意事项

- `docker/.env` 已加入 `.gitignore`，不会被提交到代码库；`.env.example` 是入库的模板
- `APP_ENCRYPTION_KEY_V1` 一旦设置不要更改，否则历史加密数据无法解密
- 全栈部署时后端连接 MinIO 使用容器内网地址（`http://minio:9000`），不是宿主机地址
- SSE 实时日志依赖 Nginx `proxy_buffering off`，配置文件已包含此设置
- 如需 HTTPS，在 `nginx/default.conf` 中增加 443 段并挂载证书
